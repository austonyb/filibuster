# 🏛️ Filibuster

**You are the senator's brain. Keep them talking — or get gaveled down.**

Filibuster is a browser game about holding the floor. A long-winded U.S. senator is
stalling a vote, and *you* feed them their next topic. A small **local LLM** turns each
topic you type into a wall of grandiose, rambling oratory — streamed live into a speech
bubble while the Senate gallery cheers, yawns, or heckles. Feed juicy, filibuster-worthy
topics and the speech rolls on. Feed dull, repetitive, or empty ones and the chamber turns
on you.

Everything runs on your machine. The speech is generated by [Ollama](https://ollama.com)
locally — no API keys, no cloud, no data leaving your computer.

---

## How it plays

You're not writing the speech — you're steering it. Each turn you type a **topic** ("the
postage stamp", "my grandmother's pie", "the sanctity of daylight savings") and the senator
fixates on it, piling on anecdotes and digressions in the florid style of a career
politician. Then the floor judges *what your topic produced*.

Two meters decide your fate, and **either one hitting zero ends the run**:

| Meter | What it is | How to keep it up |
|-------|------------|-------------------|
| 🔵 **STEAM** | Your time pressure. Drains fast while you're idle, nearly pauses while the senator talks. | Feed the next topic before it empties. Great speeches refill it. |
| 🔴 **APPROVAL** | The chamber's patience. Hecklers bleed it passively; bad topics crater it. | Hand over rich, on-topic, non-repetitive material. |

Hold the floor long enough to **kill the bill**, then move on to a harder one. Each bill
drains faster, heckles harder, and judges more strictly:

- `HR-0001` — The Daylight Savings Repeal Act
- `S-0042` — The Mandatory Broccoli Act
- `HR-1138` — The Sentient Toaster Regulation Act

### Difficulty

Pick your chamber on the menu (and again on the retry screen), from **GENTLE** (a
sympathetic crowd) up to **BEDLAM** (open revolt). Harder tiers drain faster, reward less,
punish more, and make the gallery heckle even when a speech *lands*.

### What makes a good topic?

A hidden hybrid judge scores the senator's **output**, not just your words:

- **Length** — did your topic spin into sustained oratory, or fizzle out?
- **Freshness** — looping, repetitive speech tanks the score.
- **Topicality** — did the senator actually stay on the subject you fed?

Filibuster-bait words (`constitution`, `freedom`, `grandmother`, `veterans`, the
`weather`…) are gold. One-word filler (`ok`, `bye`, `whatever`) is a dead end. Repeating
yourself bores the chamber.

## Tech

A deliberately small, dependency-light stack:

- **[Bun](https://bun.sh)** — runtime, bundler, and server. `Bun.serve()` hosts the game
  via HTML imports (no vite/webpack) and runs the WebSocket game loop (no express/ws).
- **[Phaser 4](https://phaser.io)** — the game engine (scenes, the senate-floor layout,
  meters, portraits, streaming speech panel).
- **[Ollama](https://ollama.com)** — runs the LLM locally. Defaults to `qwen3.5:2b` for
  much better topic-steering; swap in anything (e.g. the tiny `gemma3:270m`) via env var.

### How it fits together

```
Browser (Phaser)  ──WebSocket──►  Bun server (index.ts)  ──HTTP──►  Ollama
   you type a topic                 builds the prompt,                generates the
   speech streams in                streams tokens back,              senator's ramble
   meters react                     judges the output
```

The browser never talks to Ollama directly — everything routes through the Bun backend so
generation can be **streamed** and **judged** server-side, keeping CORS and the protocol
simple. The judge is a pure, unit-tested rule layer (length / repetition / topicality /
filler), so the game stays fair even when a tiny model wobbles.

## Running it

### Prerequisites

1. **[Bun](https://bun.sh)** — `curl -fsSL https://bun.sh/install | bash`
2. **[Ollama](https://ollama.com)** running locally, with a model pulled:

   ```bash
   ollama pull qwen3.5:2b      # default — good topic steering
   # or, much smaller / faster but flakier:
   # ollama pull gemma3:270m
   ```

### Install & play

```bash
bun install
bun run dev          # hot-reloading dev server
# or
bun start            # plain run
```

Then open the printed URL (default <http://localhost:3000>). The server warms the model on
boot so your first topic isn't slow.

### Configuration

All optional, via environment variables (Bun auto-loads `.env`):

| Variable | Default | Purpose |
|----------|---------|---------|
| `PORT` | `3000` | Web server port |
| `OLLAMA_URL` | `http://localhost:11434` | Where Ollama is listening |
| `FILIBUSTER_MODEL` | `qwen3.5:2b` | Which Ollama model generates the speech |

`GET /api/health` reports whether Ollama is reachable and the target model is present —
handy for debugging a blank speech bubble.

## Development

```bash
bun test             # run the judge / meter-math unit tests
```

### Project layout

```
index.ts              Bun server: HTML host, WebSocket game loop, Ollama bridge
src/
  config.ts           All tuning + layout: meters, bills, difficulties, colors
  shared/protocol.ts  WebSocket message types shared by client and server
  server/
    ollama.ts         Thin streaming client for the Ollama HTTP API
    senator.ts        Persona, prompt-building, and the pure scoring/judge logic
  scenes/             Phaser scenes: Boot → Menu → Game → End
  ui/                 Meters, portrait cards, speech panel, prompt input, difficulty slider
  net/NetClient.ts    Browser-side WebSocket wrapper
public/assets/        Optimized portraits served at runtime
assets/               Raw source art archives (gitignored)
```

Game balance lives almost entirely in `src/config.ts` — meters, drain rates, the bill
ladder, and the five difficulty tiers — so tuning the feel is a one-file job.
